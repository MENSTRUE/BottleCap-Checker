# BottleCap Checker — React Frontend (Day 23)

A real five-class bottle-cap detection dashboard, connected to the existing FastAPI service. This is a research inspection UI, not a certified production QA controller.

## Prerequisites

- Node.js 20+ and npm
- Backend running on `http://127.0.0.1:8000`
- Trusted `models/bottlecap_primary_best.pt` in the repository root

## Run (PowerShell)

.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000

Open http://127.0.0.1:5173 . The Vite proxy forwards `/api` to port `8000`. Optionally set `VITE_API_BASE_URL` in `.env.local` to a different full API base (e.g. `http://127.0.0.1:8000/api/v1`). For a remote production deployment, configure CORS correctly and restrict access to trusted users.

## Source of truth

- `/api/v1/health`: does not run inference; `model_loaded: false` is the backend's static response and **does not** imply model load failure.
- `/api/v1/models`: class order, checkpoint, and **static** research metrics read from `reports/final_summary.json`.
- `/api/v1/predict`: multipart `file`, `confidence`, `iou`, `include_annotated`. Returns real `detections`, class counts, timing and annotated JPEG in Base64.
- Exports: JSON strips Base64 and retains predictions + settings; JPG contains annotations generated by the backend.

## Supported features

- Overview: actual recorded dataset split counts and held-out research metrics.
- AI Inspection: JPEG/PNG/WebP (up to 10 MiB), drag/drop, replace, original vs annotated view, confidence and IoU controls, per-class counts and filter, JSON + JPG export.
- Model Insights: 5 class-level AP@50–95 values and transparent methodology limitations.

## Important limitations

- No product-level approval/rejection. `quality_decision` is always `not_assessed`.
- Zero boxes **never** mean the product is defect-free.
- `Good Cap` is an annotated detection class, not a blanket approval.
- Static Kaggle metrics on 112 held-out images are not real-world accuracy estimates.
- Breaking changes to backend response schemas must be reflected in `src/types/api.ts`, `src/services/api.ts` and the components.

## Troubleshooting

- `API Offline`: start backend, verify `http://127.0.0.1:8000/api/v1/health`, ensure port 8000 is not used by DefectSpot/PPE-Guard.
- `503`: verify original model path, dependency installation, see backend logs.
- `413/415/422`: upload a valid image within the limits.
- Missing `import.meta.env`: ensure `src/vite-env.d.ts` is included in TypeScript config.
- `npm run build` fails: run `npm install`, then `npm run typecheck`; don't assume a dev server proves a production build.
